4. Practical Activities

Task 1: Understanding Offensive Security

The first task introduced me to offensive security and how ethical hackers identify weaknesses in computer systems.

I learnt that offensive security involves testing systems to discover security problems before malicious attackers can take advantage of them.

This helped me understand why organisations use ethical hacking to improve their security.

Task 2: Accessing the Training Environment

I opened the FakeBank application using the virtual desktop provided by TryHackMe.

The banking website displayed account information and a negative account balance.

This activity helped me become familiar with the simulated environment before beginning the security testing.

Task 3: Scanning for Hidden Pages

I opened the Linux terminal and used the DIRB tool to scan the FakeBank website.

The command I entered was:

dirb http://fakebank.thm

The scan identified two paths:

/bank-transfer
/images
This activity showed me how directory scanning can reveal webpages that are not directly linked from a website’s main page.

I learnt that hiding a webpage does not necessarily make it secure.

Task 4: Testing the Security Weakness

After identifying the hidden bank transfer page, I accessed it through the authorised TryHackMe simulation.

I entered the account number provided in the exercise and completed a simulated deposit of $2,000.

The application confirmed that the deposit was successful and displayed the message BANK-HACKED.

This activity demonstrated how an administrative page without proper access controls can create security risks.

It also helped me understand why banking applications need strong authentication and authorisation controls.

6. Personal Reflection

Before completing this exercise, I did not have much practical experience using offensive security tools. Although I had learnt about cybersecurity concepts through my studies, I was not very confident using the Linux terminal or scanning tools.

Through this exercise, I learnt how to use a basic terminal command to identify hidden webpages. At first, some of the technical steps were unfamiliar, but following the instructions helped me understand how the tools work.

One of the most important things I learnt was that simply hiding a webpage does not make it secure. Sensitive information and administrative functions need proper authentication and access controls to prevent unauthorised access.

I also learnt the importance of carrying out security testing only in authorised environments.

If I completed a similar exercise again, I would spend more time understanding the scanning results and learning how developers can prevent these types of security weaknesses.

Overall, this activity helped me become more confident using cybersecurity tools and applying the knowledge I have gained through my university studies.
